# Codebase simplification plan

14 November 2026 · Safe cleanup completed; legacy runtime features retained.

## Completed cleanup

Corrected the backend README's obsolete feature summary, frontend test-port guidance and historical handover guidance; refined existing agent instructions. Removed the empty three-entry loop in frontend `tests/shopping-list.spec.ts`, two unused constants in `tests/price-refresh-outcomes.spec.ts` and an unused catch binding in `extensions/shopping-list/personal-comparison.js`. Their lack of effects/readers is visible in source; lint/regressions validate the cleanup. No runtime routes, worker/extension files, dependencies or retained data were removed.

Research reuses existing product, mapping, matching, library and request-coordination services. Product-library insertion now has one core for known and newly researched owned products. Product resolution can preserve existing metadata for unverified sources while browser callers retain existing enrichment behaviour. No generic executor/repository framework was introduced. Findings below retain their initial audit status; legacy retirement still needs runtime caller/configuration evidence.

Read alongside [the migration plan](ai-mcp-migration-plan.md), which owns the target architecture, proposed schema/tools, client evidence and test baseline. This document owns cleanup evidence. Existing operational contracts remain in [AI connections](AI_CONNECTIONS.md), [MCP security](MCP_SECURITY.md), [release readiness](RELEASE_READINESS.md) and `TECHNICAL_GUIDE.md`; do not duplicate them into another general architecture document.

## Inventory and assessment

Backend has 454 tracked files: 266 application C# files excluding migrations/tests, 94 `*Tests.cs` files and 26 migration implementations. Frontend has 195 tracked files, including 103 source TS/TSX files and 12 extension runtime JS files. Counts are from `git ls-files`, not ignored build/cache directories. File count is context, not a quality target. Both trees were clean before the audit; only two requested documents are added on the backend audit branch.

The project already has a sensible service/endpoint separation and no generic repository layer to remove. Complexity mainly comes from coexistence of legacy shared-import/discovery queues, private capture/comparison flows and the newer own-device MCP bridge. There is genuine repeated discovery orchestration and conflicting documentation. There is insufficient evidence to declare all legacy code dead: entry points, feature flags, workers, endpoint mappings, extension manifests and regression suites still reference it. Runtime deployment configuration and external callers were not inventoried from production.

## Ordered cleanup tasks

1. **Documentation correction only.** Update the specific README/handover passages above, mark historical audit slices and link the new direction. Preserve current operational contracts and all existing functionality. Check source links, port instructions and disabled-by-default claims. This is the safest first simplification.
2. **Refine existing agent instructions.** Add concise rules to backend `AGENTS.md`: domain services own rules; MCP is an adapter; reuse before adding; evidence is untrusted; no fictitious verification; minimal dependencies; safe additive migration/rehearsal; prove all entry points before deletion; document scope/tests/risks in PRs. Reference the backend rules from frontend instructions where useful, retaining Next's generated block. Apply session-specific authorization as instructed by the owner; do not rewrite approval rules as a side effect of this audit.
3. **Implement read-only research instructions/context first.** This is the first feature task, described in the migration plan. It tests the new direction with no schema change, no paid provider and no retailer execution.
4. **Refactor the evidence/persistence seam with meaningful tests.** Introduce only the common validation actually required by extension and AI sources. Preserve lock order, price provenance and rollback; never accept an arbitrary AI report as a browser observation. Then add the minimal research schema/submission/review.
5. **After replacement acceptance, decide legacy retirement.** Measure configured callers and pending/retained work for the legacy worker, import and discovery paths. Retain optional customer capture/refresh; extension removal remains a separate explicit product decision. Prefer retiring confirmed obsolete paths over building another common executor framework.
6. **Final review.** Recheck DI/route/tool inventories, dynamic extension entry points, gateway allowlists, dependency consumers, account export/deletion, retention and documentation. Record additions/removals/remaining legacy code in each focused PR. Do not merge/deploy automatically.

The current audit executed a fresh database-free API baseline (**2,713 passed, 406 skipped, 0 failed**) and frontend/extension Node baseline (**173 passed, 1 skipped, 0 failed**). Frontend TypeScript passed; lint returned **0 errors, 5 existing warnings**. Both reports passed local Markdown-link and trailing-whitespace checks. For future runtime changes, run affected matching/price/list/extension unit suites, then relational suites on an explicitly disposable PostgreSQL target. Fixtures can commit data and some migration fixtures create/drop schemas; never aim them at the application database. Preserve the existing ownership, replay, grant revocation and source-isolation checks. Run responsive browser journeys for changed flows, using port 3001 only after checking availability; never stop the user's 3000 server. The initial phase creates no migrations, changes no subscription rules, removes no extension and needs no deployment. Remaining release prerequisites are actual client-account tests, evidence-policy acceptance, migration rehearsal/target selection, TLS/keys/registered callbacks and any eventual retirement decision. They are documented without interrupting this audit for approvals.
